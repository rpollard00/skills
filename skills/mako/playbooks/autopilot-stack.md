# Autopilot-stack

Build and verify the queue, then hand the operator the PRs to review and land. Keep independent PRs independent, per [Shipping](shipping.md). Stack a PR only on work it actually depends on. Do not merge, enable auto-merge, or close PRs as delivery.

1. Establish the scope, order, completion predicate, budget, and operator gates. A plan-only request stops after the plan. A request to build the stack proceeds without another permission checkpoint.
2. Read [execution](../references/execution.md). Select one continuation owner. Assign owners with the lifecycle and decision records from [Autopilot-full](autopilot-full.md), excluding merge authority.
3. Parallelize independent implementation only. Each owner has an isolated writable location and reports its exact head, current base, and intended dependencies. Independent PRs run self-proof and [Babysit](babysit.md) under their own owners. Sequence dependent work against its required parent. A shared landing owner or delivery order does not create a dependency.
4. Follow Autopilot-full's verification cadence: a full swarm at the code-ready head and after new behavior, a redesign, or a large new diff. A rebase, conflict resolution, or minor fix gets one independent verifier at the new head. The owner reports `STACK-READY` with its exact revision, including for an independent PR. Nothing enters the delivered queue without current checks, live proof, an evidence audit, and a passing verdict.
5. For each dependency stack, keep one topology owner. Only that owner coordinates rebases, retargets, and stack publication. Other owners must stop writes to affected resources during those operations. Before admitting a PR, end its owner's independent babysit loop and hand monitoring to the single stack babysitter. The stack babysitter coordinates readiness across all admitted PRs. PR owners retain assigned repairs and self-proof, not separate stack-wide loops. Dependent PRs join this coordination from creation. Independent PRs stay outside these stacks and retain their own ownership and monitoring.
6. Each independent PR and each stack root targets trunk. Each dependent child targets its intended parent's exact revision and branch. Record each head and base as repository identity (including forge host) plus branch name. Match a child's base to its parent's head using both fields. Same-named branches in different repositories, including forks, are different branches. Use Git branches and native worktrees for isolation. Only the topology owner rebases or retargets its stack; do not reset a dirty checkout.
7. Until operator landing starts, absorb base drift bottom-up within each dependency stack when required. Independent owners handle their own base drift. Coordinate conflict repairs with the affected owner. Apply execution's publication ownership rule at every handoff and push. After a topology-owner push, the PR owner explicitly takes over that revision before publishing again. Re-run checks and mergeability after rewritten publication, then apply [Shipping's evidence freshness rules](shipping.md) to each affected verdict.
8. Reconcile children, ownership, and evidence at lifecycle events and driver checkpoints. Investigate stalls, then replace stuck writers immediately under execution's handoff rule, without waiting for stop confirmation. Propagate an operator hold immediately and verify safe state.
9. Deliver the independent PRs and dependency stacks with each verdict and evidence reference in the relevant PR. The operator reviews and lands them. Preserve protected-limit approvals and other reserved gates.
10. When operator landing starts, transfer topology ownership for the affected PRs to the operator or their named landing owner. Freeze other agent writes to those PRs, including repairs, rebases, retargets, and publication. Report problems to the operator and wait for explicit repair direction. Only the landing owner performs authorized post-merge retargeting through Shipping.

Choose Autopilot-full when the run has merge authority. Choose this route when the operator retains landing authority. Determine dependency topology separately in either route.

Report every PR link, each stack's root and tip links, intended dependencies and head per PR, and verification state. Include parked work and open operator gates. Do not call merge-ready work merged.
